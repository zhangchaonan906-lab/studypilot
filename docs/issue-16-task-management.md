# Issue 16：任务编辑、新增、删除

## 背景

StudyPilot 公测反馈中，用户提到：

1. AI 生成的任务不一定完全符合预期
2. 学习计划生成后不能修改
3. 用户希望能手动调整任务
4. 用户希望能新增自己的任务
5. 用户希望能删除不合适的任务

本 Issue 先只做任务级管理，不做计划标题、目标、deadline 编辑。

## 目标

在 `/plans/\\\[id]` 页面支持：

1. 编辑任务
2. 新增任务
3. 删除任务

让用户可以管理 AI 生成后的学习任务。

## 不能做的事情

1. 不修改数据库 schema
2. 不修改 Supabase RLS policy
3. 不修改 AI provider
4. 不修改 DeepSeek / OpenAI 逻辑
5. 不做 AI 重新生成某一天
6. 不做 AI 对话式修改计划
7. 不做计划标题 / 目标 / deadline 编辑
8. 不做拖拽排序
9. 不做批量编辑
10. 不提交 `.env.local`
11. 不暴露任何 API Key

## 必须保持正常的已有功能

1. 登录注册
2. AI 生成学习计划
3. 今日任务打卡 / 取消打卡
4. 每日复盘
5. 错题复习
6. 每周总结
7. loading / 进度条
8. YouTube / B站资源搜索链接
9. 删除学习计划功能
10. Dashboard 完成率统计

## 一、任务编辑

在 `/plans/\\\[id]` 页面，每个 task 增加“编辑”入口。

允许编辑：

1. `content`
2. `estimated\\\_minutes`
3. `priority`

priority 只能是：

* `must`
* `should`
* `optional`

交互要求：

1. 点击“编辑”后进入编辑状态
2. 显示一个轻量表单
3. 用户可以修改任务内容、预计时间、优先级
4. 点击“保存”
5. 保存中按钮 disabled，并显示“保存中...”
6. 保存成功后退出编辑状态，并更新页面数据
7. 点击“取消”后恢复原任务内容
8. 保存失败显示中文错误：  
“任务更新失败，请稍后重试。”

权限要求：

1. 用户只能编辑自己的任务
2. 不允许编辑其他用户的任务
3. 更新操作必须基于当前登录用户
4. 不使用 service role key
5. 如果 task 不存在或不属于当前用户，返回：  
“任务不存在或无权修改。”

## 二、新增任务

在 `/plans/\\\[id]` 的每个 day 卡片中增加“新增任务”入口。

新增字段：

1. `content`
2. `estimated\\\_minutes`
3. `priority`

默认 priority 可以是 `should`。

交互要求：

1. 点击“新增任务”后显示表单
2. 用户填写任务内容、预计时间、优先级
3. 点击“保存”
4. 保存中按钮 disabled，并显示“保存中...”
5. 新增成功后，当前 day 的任务列表立即更新
6. 新增失败显示中文错误：  
“任务创建失败，请稍后重试。”
7. 可以取消新增

权限要求：

1. 用户只能给自己的 plan\_day 新增任务
2. 不允许给别人的 plan\_day 新增任务
3. 不使用 service role key

## 三、删除任务

每个 task 增加“删除”入口。

交互要求：

1. 点击删除前必须确认
2. 可以使用浏览器原生 confirm
3. 确认文案：  
“确定删除这个任务吗？删除后无法恢复。”
4. 用户取消时，不删除任务
5. 用户确认后删除任务
6. 删除中按钮 disabled，并显示“删除中...”
7. 删除成功后，任务从页面移除
8. 删除失败显示中文错误：  
“任务删除失败，请稍后重试。”

权限要求：

1. 用户只能删除自己的任务
2. 不允许删除别人的任务
3. 不使用 service role key

## 四、数据一致性

1. 编辑 `estimated\\\_minutes` 后，页面显示要同步变化
2. 编辑 `priority` 后，badge / 标签要同步变化
3. 新增任务后，计划详情页能显示新任务
4. 删除任务后，计划详情页不再显示该任务
5. 删除已完成任务后，完成率统计不能报错
6. 不要破坏 `/today` 的打卡和取消打卡逻辑
7. Dashboard 完成率应能正常重新计算
8. 如果没有任务，要显示友好空状态，不要报错

## 五、UI 要求

1. 保持当前 StudyPilot UI 风格
2. 编辑入口不要太抢眼，但要容易找到
3. 表单简洁，不要让 `/plans/\\\[id]` 页面变乱
4. 移动端可用
5. 按钮文案使用中文：

   * 编辑
   * 保存
   * 取消
   * 新增任务
   * 删除
   * 保存中...
   * 删除中...
6. 错误提示用中文
7. 不要引入大型 UI 库

请优先复用现有数据访问层。

如果已有 task CRUD 相关方法，请完善它们。

如果没有，请在合适的数据访问文件中新增最小方法：

1. `updateTask`
2. `createTask`
3. `deleteTask`

这些方法必须：

1. 校验当前用户
2. 只能操作当前用户自己的数据
3. 不使用 service role key
4. 返回清晰错误
